# v0.4 - Memory Management

---

## Step 0: Theory of memory in AArch64

For this part, I used the official [Learn the architecture - AArch64 memory management](https://support.arm.com/documentation/101811/0105) guide.

### Address spaces

#### Virtual addresses

Software running on the CPU does not use physical addresses directly. It uses **virtual addresses**. Every load, store and instruction fetch is translated by the hardware into a physical address before reaching memory.

Virtual addressing allows:

- **Isolation**: each program can have its own view of memory.
- **Flexibility**: the same physical page can appear at several virtual addresses or a contiguous virtual range can be backed by scattered physical pages.
- **Control**: permissions and memory attributes are attached to each mapping.

#### Physical addresses

A **physical address** identifies a location in the system's physical memory map (RAM or peripherals like MMIO). On QEMU `virt`, for example:

| Region | Physical address |
| --- | --- |
| GIC | `0x08000000` |
| UART | `0x09000000` |
| RAM | `0x40000000` |

Before v0.4, the CPU ran with the MMU off, meaning that virtual address was equal to the physical one.

#### Sizes

Addresses are held in 64-bit registers, but not all 64 bits are used.

- A virtual address is typically **48 bits** wide (configurable through `TCR_EL1`).
- The bits above must all be equal (`0` or `1`), such an address is called *canonical*.
- For bit 63..48 , if all bits are  `0` it selects the **lower** virtual address range (translated through `TTBR0_EL1`) and if all `1` it selects the **upper** range (`TTBR1_EL1`). A kernel is often placed in the upper range, and user programs in the lower one.
- The size of the physical address space is implementation defined (up to 48 bits, more with extensions). It is reported in `ID_AA64MMFR0_EL1`.

```text
 63            48 47                                   0
 +----------------+-------------------------------------+
 | all 0 / all 1  |          48-bit virtual address     |
 +----------------+-------------------------------------+
   0000... -> TTBR0_EL1 (lower range)
   1111... -> TTBR1_EL1 (upper range)
```

### The Memory Management Unit

The **MMU** is the hardware block that performs the vitual address to physical address translation. It:

1. **Translates** virtual addresses into physical addresses.
2. **Checks permissions** (read/write, privileged/unprivileged, executable or not).
3. **Applies memory attributes** (Device or Normal memory, cacheability, shareability).

It is made of a **table walk unit**, which reads the translation tables stored in memory, and of **TLBs** (Translation Lookaside Buffers), small caches of recent translations, so that the tables do not have to be walked at every access.

The MMU is enabled with bit 0 (`M`) of `SCTLR_EL1`. With it off, no translation happens (and all data accesses are treated as Device memory). Each exception level has its own *translation regime*; for a kernel at EL1, the registers of interest are:

| Register | Role |
| --- | --- |
| `SCTLR_EL1` | Enables the MMU (`M`), data cache (`C`), instruction cache (`I`) |
| `TCR_EL1` | Translation control: granule, virtual address size (`T0SZ`/`T1SZ`), table walk attributes |
| `TTBR0_EL1` | Base address of the translation tables for the lower virtual address range |
| `TTBR1_EL1` | Base address of the translation tables for the upper virtual address range |
| `MAIR_EL1` | Memory attribute definitions (Device, Normal...), referenced by index in the descriptors |

### Translation tables

#### Granule and levels

The **translation granule** is the smallest block of memory that can be mapped: 4 KB, 16 KB or 64 KB. This project uses **4 KB**.

With a 4 KB granule, a 48-bit virtual address is split into a page offset and four 9-bit indexes, one per **translation level**:

```text
 47      39 38      30 29      21 20      12 11          0
 +---------+----------+----------+----------+-------------+
 | L0 idx  |  L1 idx  |  L2 idx  |  L3 idx  | page offset |
 +---------+----------+----------+----------+-------------+
   9 bits     9 bits     9 bits     9 bits      12 bits
```

Each table holds 512 entries of 8 bytes, i.e. exactly 4 KB: one table fits in one page.

#### The table walk

Starting from the base address in `TTBR0_EL1`, the MMU walks the tables one level at a time:

```text
TTBR0_EL1 --> L0 table --[L0 idx]--> L1 table --[L1 idx]--> L2 table --[L2 idx]--> L3 table --[L3 idx]--> page
                                                                                                 |
                                                       physical page address + page offset = PA
```

Each entry either points to the next-level table, describes a block or is invalid.

| Level | Entry can be | Size covered by one entry (4 KB granule) |
| --- | --- | --- |
| L0 | table | 512 GB |
| L1 | table or block | 1 GB |
| L2 | table or block | 2 MB |
| L3 | page | 4 KB |

Blocks are convenient for large regions (for example the RAM or a peripheral area) since they need fewer tables.

#### Descriptors

Each entry is a 64-bit **descriptor**. Its low bits tell what it is:

| Bits [1:0] | Meaning |
| --- | --- |
| `0b00` / `0b10` | Invalid (accessing it raises a translation fault) |
| `0b01` | Block (L1, L2) |
| `0b11` | Table (L0, L1, L2) or page (L3) |

A block or page descriptor also carries:

- the **output address** (bits [47:12] for a page): the physical address it maps to;
- `AttrIndx`: index into `MAIR_EL1`, selects the memory type;
- `AP`: access permissions (read-only or read-write, EL0 access);
- `SH`: shareability;
- `AF`: access flag (must be set, otherwise an access raises a fault);
- `PXN` / `UXN`: privileged / unprivileged execute-never.

### What this means for the kernel

For v0.4:

- 4 KB granule, 48-bit virtual addresses, translation through `TTBR0_EL1` only at first.
- Memory types: **Normal** for the RAM, **Device** for the UART and the GIC.
- First an identity mapping (virtual address = physical address) to turn the MMU on without moving anything, then more elaborate mappings (aliases, permissions).
- Faults (translation or permission) come back as synchronous exceptions, with the cause in `ESR_EL1` and the faulting address in `FAR_EL1`. This is why the fault diagnostics come before the MMU activation in the plan.

## Step 1: Physical memory layout

### The memory map

On QEMU `virt`, the RAM starts at `0x40000000` (see [notes/v01.md](v01.md)). The kernel is loaded at the very beginning of it, and everything after the end of the image is free RAM that the physical memory manager will hand out.

```text
 0x40000000  _kernel_start
    |        .text
    |        .rodata
    |        .data
    |        .bss          (_bss_start .. _bss_end)
    |        .stack        (_stack_bottom .. _stack_top, 64 KB)
 _kernel_end
    |        (padding up to the next 4 KB )
 _heap_start (4 KB aligned)
    |
    |        free RAM, managed by the physical allocator
    |
 RAM_END     0x48000000  (RAM_BASE + 128 MB), first address outside the RAM
```

The last usable byte is at `RAM_END - 1`.

### Linker symbols

The linker script exports symbols describing the layout of the image, so that the code does not have to hardcode any address:

| Symbol | Meaning |
| --- | --- |
| `_kernel_start` | Beginning of the image (`0x40000000`) |
| `_bss_start` / `_bss_end` | Bounds of `.bss`, both 8-byte aligned |
| `_stack_bottom` / `_stack_top` | Bounds of the boot stack |
| `_kernel_end` | End of the image |
| `_heap_start` | `_kernel_end` rounded up to 4 KB |

`linker.ld`:

```text
ENTRY(_start)

SECTIONS
{
    . = 0x40000000;
    _kernel_start = .;


    .text : {
        *(.text*)
    }

    .rodata : {
        *(.rodata*)
    }

    .data : {
        *(.data*)
    }

    . = ALIGN(8);
    .bss : {
        _bss_start = .;
        *(.bss*)
        . = ALIGN(8);
        _bss_end = .;
    }

    . = ALIGN(16);

    .stack :
    {
        _stack_bottom = .;
        . += 0x10000;
        _stack_top = .;
    }
    _kernel_end = .;

    . = ALIGN(4096);
    _heap_start = .;
}
```

- `. = ALIGN(8)` around `.bss` guarantees that the zeroing loop below, which writes 8 bytes at a time, stops exactly on `_bss_end`.
- `_kernel_end` is the real end of the image.

### Shared constants

`src/mm/mm.inc`, included like `gic.inc` by the files that need it:

```asm
.equ RAM_BASE,      0x40000000
.equ RAM_SIZE,      0x8000000
.equ RAM_END,       RAM_BASE + RAM_SIZE
.equ PAGE_SHIFT,    0xC
.equ PAGE_SIZE,     0x1 << PAGE_SHIFT
```

- `RAM_SIZE` is in bytes: `0x8000000` = 128 MB.
- `RAM_END` is a constant and not a linker symbol: the size of the RAM comes from QEMU. It must stay consistent with the `-m 128M` option used to launch QEMU, nothing checks it automatically.
- `PAGE_SIZE` = `1 << 12` = 4096 bytes, the translation granule chosen in Step 0.

### Zeroing the `.bss`

By the C convention, `.bss` holds uninitialized variables (here `tick_count`) that must start at zero. QEMU loading an ELF already zero-fills it, so the kernel worked without it, but this would not hold with a raw binary image or on real hardware. Since the physical allocator will rely on zero-initialized state, the kernel now clears `.bss`, right after setting the stack pointer, in `src/boot/boot.s`:

```asm
_start:
    ldr x0, =_stack_top
    mov sp, x0

    ldr x0, =_bss_start
    ldr x1, =_bss_end

bss_loop:
    cmp x0, x1
    b.hs bss_done
    str xzr, [x0], #8
    b bss_loop

bss_done:
    ldr x0, =message
    bl uart_puts
    ...
```

- `ldr x0, =_bss_start` loads the address of the start of `.bss`.
- `cmp` + `b.hs` is an unsigned comparison. The test is at the top of the loop, so an empty `.bss` writes nothing.
- `str xzr, [x0], #8` writes 8 zero bytes (`xzr` always reads as zero) at `[x0]`, then increments `x0` by 8 (like `ldrb w0, [x19], #1` in `uart_puts`).

## Step 2: Fault diagnostics

### Why

Once the MMU is enabled, most mistakes (unmapped address, wrong permissions, bad alignment on Device memory) become synchronous exceptions. The handler already dumped `ELR_EL1` (which instruction faulted), `SPSR_EL1` and `ESR_EL1` (what kind of exception), but not **which address** was accessed. That is the role of `FAR_EL1`, the Fault Address Register.

> See the `ESR_EL1` and `FAR_EL1` descriptions in the [Arm Architecture Reference Manual (DDI 0487)](https://developer.arm.com/documentation/ddi0487/latest).

### Decoding `ESR_EL1`

- Bits [31:26]: **EC** (Exception Class), the type of exception.
- Bits [24:0]: **ISS**, details that depend on the EC.

| EC | Meaning |
| --- | --- |
| `0x00` | Unknown reason |
| `0x15` | `SVC` executed in AArch64 |
| `0x20` / `0x21` | Instruction abort from a lower EL / the same EL |
| `0x22` | PC alignment fault |
| `0x24` / `0x25` | Data abort from a lower EL / the same EL |
| `0x26` | SP alignment fault |

For a data abort (`EC = 0x25`), the low bits of the ISS (`DFSC`, bits [5:0]) give the fault type, where `LL` is the translation level:

| `DFSC` | Fault |
| --- | --- |
| `0b0001LL` | Translation fault |
| `0b0010LL` | Access flag fault |
| `0b0011LL` | Permission fault |
| `0b100001` | Alignment fault |

Bit 6 (`WnR`) tells whether the access was a write.

`FAR_EL1` is only meaningful for aborts and alignment faults. For an `SVC` its value is not significant.

### Saving `FAR_EL1`

In `CALL_HANDLER` (`src/exceptions/vectors.s`), `FAR_EL1` is read together with the other registers, before the handler does anything else: a new fault would overwrite it.

```asm
.macro CALL_HANDLER handler
vector_\handler:
    mrs x19,  ELR_EL1
    mrs x20,  SPSR_EL1
    mrs x21,  ESR_EL1
    mrs x22,  FAR_EL1

    mov x0, sp

    bl \handler
.endm
```

`x19` to `x22` are callee-saved: they survive the `uart_puts` and `uart_put_hex` calls made by the handler.

Since `x22` is now taken by `CALL_HANDLER`, `el_irq` moved to the next registers: the interrupt ID read from `GICC_IAR` is kept in `x23` (it was `x22`), and the tick counter in `x24` (it was `x23`).

### Printing the EC and `FAR_EL1`

In `el_synchronous` (`src/exceptions/handlers.s`):

```asm
    // x19/x20/x21/x22 set by CALL_HANDLER
    ...
    ldr x0, =message_prefix_ec
    bl uart_puts
    lsr x0, x21, #26
    and x0, x0, #0x3F
    bl uart_put_hex

    ldr x0, =message_prefix_far_el1
    bl uart_puts
    mov x0, x22
    bl uart_put_hex
```

- `lsr x0, x21, #26` shifts the EC field down to the lowest bits.
- `and x0, x0, #0x3F` keeps 6 bits: recent architectures use bits above 31 of `ESR_EL1`.

and the two new prefixes in `.rodata.handlers`, padded so that the values line up with the other lines:

```asm
message_prefix_ec:
    .asciz "\nEC:       0x"

message_prefix_far_el1:
    .asciz "\nFAR_EL1:  0x"
```

### Run

```bash
make clean && make
qemu-system-aarch64 -M virt -cpu cortex-a57 -m 128M -nographic -kernel build/kernel.elf
```

```text
Hello, AArch64!

Synchronous exception caught!
ELR_EL1:  0x0000000040000040
SPSR_EL1: 0x0000000040000345
ESR_EL1:  0x0000000056000000
EC:       0x0000000000000015

```

- `EC = 0x15` confirms the `svc #0`.
- `FAR_EL1` is not meaningful here: an `SVC` is not an abort. It will be used with real data aborts once the MMU is enabled.
- `GICC_IAR` is still `0`, now read from `x23`.

### Limitations

- **The interrupted context is not saved.** The handlers overwrite `x0`-`x3` (UART calls, `timer_set_interval`) and `x19`-`x24`. This is harmless today because `_start` does nothing useful after unmasking IRQs, but any initialization code running with IRQs unmasked would see its registers corrupted by the timer IRQ. For v0.4, all memory initialization therefore runs **before** `msr daifclr, #2`. A proper context save comes with multitasking (v0.6).
- **`eret` after a real abort would loop.** For an `SVC`, `ELR_EL1` points to the instruction after the `svc`. For an abort, it points to the faulting instruction itself, so an `eret` would run it again and fault forever. Fault tests (Step 6) will need a handler that halts, or that advances `ELR_EL1` before returning.

## Step 3: Physical page allocator

### Goal

Page tables (Step 4) are made of 4 KB pages that must be obtained from somewhere. The physical page allocator hands out the free pages of the RAM, one 4 KB page at a time, between `_heap_start` and `RAM_END`.

> Inspired by `kernel/kalloc.c` in [xv6-riscv](https://github.com/mit-pdos/xv6-riscv).

### The free list

Free pages are chained in a free list. Each free page stores, in its first 8 bytes, the address of the next free page. A variable in `.bss` (`free_list_head`) points to the first one, and `free_count` keeps the number of free pages.

```text
free_list_head --> [page A] --> [page B] --> [page C] --> 0
                   (first 8 bytes = address of the next page)
```

- `page_free` inserts a page at the head.
- `page_alloc` removes the page at the head and zeroes it.

### Functions

| Function | Input | Output | On error |
| --- | --- | --- | --- |
| `page_free` | `x0` = page address | none | Halts with a message if the address is misaligned or outside `[_heap_start, RAM_END[` |
| `page_alloc` | none | `x0` = page address, zeroed | Returns `0` if no page is left (callers must check) |
| `pmm_init` | none | none | none |

The two error policies are intentionally different. An invalid address given to `page_free` is a kernel bug, so we are halting immediately. Running out of pages is a possible situation, so the allocator reports it and the caller decides what to do.

> The code can be viewed at [src/mm/pmm.s](../src/mm/pmm.s).

### Register conventions

`page_free` and `page_alloc` call no other function, so they only use caller-saved registers (`x0`-`x4`) and save nothing. `pmm_init` calls `page_free` in a loop and must keep its pointer and its end bound across the calls, I decided to place them in the callee-saved registers `x19` and `x20`, which `pmm_init` saves on the stack and restores. `x30` (return address) is saved too, since each `bl` overwrites it. The frame is 32 bytes to keep `sp` 16-byte aligned.

### Calling `pmm_init`

In `src/boot/boot.s`, after `VBAR_EL1` is set (so that a failure can at least print through the exception handlers) and **before** IRQs are unmasked: the handlers do not save the interrupted context, so an IRQ in the middle of `pmm_init` would corrupt its registers.

```asm
    ldr x0, =_exception_vector_table
    msr vbar_el1, x0

    bl pmm_init

    bl gic_init
```

### Order of the pages

`pmm_init` frees the pages in increasing order and `page_free` inserts at the head, so the list is in decreasing order, then the first page returned by `page_alloc` is the highest one (`0x47FFF000`), then `0x47FFE000`, and so on.

### Verification

The number of free pages is computed by hand:

```text
(RAM_END - _heap_start) / PAGE_SIZE = (0x48000000 - 0x40012000) / 0x1000 = 0x7FEE
```

A temporary test in `_start` (it will move to a proper self-test in Step 8) prints the number of free pages after `pmm_init`, allocates one page, prints its address and the new count, then gives the page back:

```asm
    // Initialize the physical memory manager
    bl pmm_init

    ldr x0, =message_free_pages
    bl uart_puts
    ldr x0, =free_count
    ldr x0, [x0]
    bl uart_put_hex

    // Allocate a page
    bl page_alloc
    mov x19, x0                 // x0 is overwritten by the UART calls

    ldr x0, =message_alloc
    bl uart_puts
    mov x0, x19
    bl uart_put_hex

    // Print the number of free pages after the allocation
    ldr x0, =message_free_pages
    bl uart_puts
    ldr x0, =free_count
    ldr x0, [x0]
    bl uart_put_hex
    mov w0, #10                 // newline
    bl  uart_putc

    // Give the page back
    mov x0, x19
    bl page_free
```

`x19` is callee-saved, so it keeps the page address across the UART calls without any stack frame in `_start`.

Output:

```text
Hello, AArch64!

Free pages: 0x0000000000007FEE
Alloc: 0x0000000047FFF000
Free pages: 0x0000000000007FED

Synchronous exception caught!
ELR_EL1:  0x000000004000008C
...
```

- `0x7FEE` matches the computed value.
- The first allocated page is the highest one (`0x47FFF000`), as explained above, and the counter decreases by one.
- The rest of the output is unchanged. `ELR_EL1` moved from `0x40000040` to `0x4000008C` because the test code now sits before the `svc`, and `SPSR_EL1` shows the `N` flag (`0x80000345`) inherited from the last `cmp` executed before it.

## Step 4: Page tables

### Goal

Build the translation tables that describe which virtual address maps to which physical address.

> See the [Learn the architecture - AArch64 memory management](https://support.arm.com/documentation/101811/0105) guide.

### Table layout

With the 4 KB granule chosen in Step 0, a 48-bit virtual address is split into four 9-bit indexes and a 12-bit offset:

```text
 47      39 38      30 29      21 20      12 11          0
 +---------+----------+----------+----------+-------------+
 | idx L0  |  idx L1  |  idx L2  |  idx L3  | page offset |
 +---------+----------+----------+----------+-------------+
```

A table has 512 entries of 8 bytes, exactly one 4 KB page, so every table comes from the page allocator of Step 3.

### Descriptors

Each entry is a 64-bit descriptor. Bits [1:0] give its type:

| Bits [1:0] | Levels 0-2 | Level 3 |
| --- | --- | --- |
| `0b00` | invalid | invalid |
| `0b01` | block (not used here) | reserved |
| `0b11` | **table**: points to the next-level table | **page**: maps a 4 KB page |

A table descriptor is `address of the next table | 0b11`. 
A page descriptor adds attributes:

| Field | Bits | Meaning |
| --- | --- | --- |
| Type | [1:0] | `0b11` = valid page |
| AttrIndx | [4:2] | Index into `MAIR_EL1` (memory type) |
| AP[2] | 7 | 1 = read-only |
| SH | [9:8] | Shareability (`0b11` = inner shareable) |
| AF | 10 | Access Flag, must be 1 or the first access faults |
| Address | [47:12] | Physical address of the page |
| PXN | 53 | Privileged execute-never |
| UXN | 54 | Unprivileged execute-never |

### Constants

`src/mm/mm.inc` names every field, so that no magic number appears in the code:

```asm
// ------------------------------------------------------------------
// Translation table descriptors (4 KB granule)
// ------------------------------------------------------------------

// Bits [47:12]: output address (next table, or physical page).
.equ DESCR_ADDR_MASK,    0x0000FFFFFFFFF000

// Bits [1:0]. 0b11 means "table" at levels 0-2 and "page" at level 3.
.equ DESCR_VALID,        1
.equ DESCR_TYPE_TABLE,   0b11
.equ DESCR_TYPE_PAGE,    0b11

// Page attributes
.equ DESCR_AF,           (1 << 10)      // Access Flag
.equ DESCR_SH_INNER,     (0b11 << 8)    // Shareability
.equ DESCR_AP_RO,        (1 << 7)       // AP[2]: read-only
.equ DESCR_PXN,          (1 << 53)      // Privileged execute-never (EL1)
.equ DESCR_UXN,          (1 << 54)      // Unprivileged execute-never (EL0)

// Memory type, index into MAIR_EL1
.equ MT_DEVICE,          0
.equ MT_NORMAL,          1

// Indexes shifted into the AttrIndx field, bits [4:2].
.equ DESCR_MT_DEVICE,    (MT_DEVICE << 2)
.equ DESCR_MT_NORMAL,    (MT_NORMAL << 2)

// ------------------------------------------------------------------
// Page profiles
// ------------------------------------------------------------------

.equ PAGE_RAM,           (DESCR_MT_NORMAL | DESCR_AF | DESCR_SH_INNER | DESCR_UXN)
.equ PAGE_DEVICE,        (DESCR_MT_DEVICE | DESCR_AF | DESCR_PXN | DESCR_UXN)
```

- `PAGE_RAM`: Normal memory, executable by the kernel.
- `PAGE_DEVICE`: Device memory, never executable.

### `map_page`

`src/mm/pgtable.s`:

```asm
map_page:
    stp x19, x20, [sp, #-16]!
    stp x21, x22, [sp, #-16]!
    stp x23, x24, [sp, #-16]!
    stp x30, xzr, [sp, #-16]!

    mov x19, x0          // current table (starts at the root)
    mov x20, x1          // virtual address
    mov x21, x2          // physical address
    mov x22, x3          // attributes
    mov x23, #39         // shift of the current level (39, 30, 21)

.Llevel_loop:
    lsr x1, x20, x23
    and x1, x1, #0x1FF
    add x24, x19, x1, lsl #3
    ldr x2, [x24]

    tst x2, #1
    b.ne .Ldown_level

    bl page_alloc
    cbz x0, .Lerror_map_page

    orr x2, x0, #DESCR_TYPE_TABLE
    str x2, [x24]

.Ldown_level:
    and x19, x2, #DESCR_ADDR_MASK
    sub x23, x23, #9
    cmp x23, #12
    b.hi .Llevel_loop

    // Level 3
    lsr x1, x20, #12
    and x1, x1, #0x1FF
    add x24, x19, x1, lsl #3

    orr x2, x21, x22
    orr x2, x2, #DESCR_TYPE_PAGE
    str x2, [x24]

    ldp x30, xzr, [sp], #16
    ldp x23, x24, [sp], #16
    ldp x21, x22, [sp], #16
    ldp x19, x20, [sp], #16
    ret

.Lerror_map_page:
    ldr x0, =error_map_page_message
    bl  uart_puts
    mov x0, x20
    bl  uart_put_hex
    b .
```

The function walks levels 0, 1 and 2 in a loop, then writes the page descriptor at level 3.

For each level:

1. `lsr x1, x20, x23` then `and x1, x1, #0x1FF` extract the 9-bit index. It shift the virtual address right by `shift` (39, 30, 21) and keep 9 bits.
2. `add x24, x19, x1, lsl #3` computes the address of the entry: `table + index * 8`.
3. If bit 0 of the entry is set, the next table already exists and is reused.
4. Otherwise `page_alloc` provides a new, zeroed table, and the entry becomes `address | 0b11`. Both paths reach `.Ldown_level` with the table descriptor in `x2`.
5. `and x19, x2, #DESCR_ADDR_MASK` strips the type bits and gives the address of the next table. Without the mask, the next table would be read at an unaligned address such as `0x47FFE003`.
6. `shift` decreases by 9. The loop stops when it reaches 12: the table in `x19` is then the level 3 table.

At level 3, nothing is allocated, the entry is `pa | attributes | 0b11`.

`map_page` calls `page_alloc`, which overwrites `x0`-`x4`. Everything that must survive the call is therefore in a callee-saved register, saved on the stack:

| Register | Content |
| --- | --- |
| `x19` | current table |
| `x20` | virtual address |
| `x21` | physical address |
| `x22` | attributes |
| `x23` | shift of the current level |
| `x24` | address of the current entry |

`x24` matters the most. The entry address is computed before `page_alloc` and used after it, to store the new descriptor. The index in `x1` would not survive the call. The frame is 64 bytes (seven registers rounded up to eight slots, with `xzr` as padding) to keep `sp` 16-byte aligned.

If `page_alloc` returns 0, `map_page` prints the faulty virtual address and halts.

### `translate`

`translate` walks the tables the way the MMU will, but in software and read-only. It, only, prints the descriptor found at each level and returns the physical address, or 0 if the address is not mapped.

```asm
translate:
    stp x19, x20, [sp, #-16]!
    stp x21, x22, [sp, #-16]!
    stp x23, x30, [sp, #-16]!

    mov x19, x0          // current table (starts at the root)
    mov x20, x1          // virtual address
    mov x21, #39         // shift of the current level (39, 30, 21)
    mov x22, #0          // Level counter

.Ltranslate_loop:
    lsr x1, x20, x21
    and x1, x1, #0x1FF
    add x2, x19, x1, lsl #3
    ldr x23, [x2]

    ldr x0, =level_message
    bl uart_puts
    add w0, w22, #48
    bl uart_putc
    ldr x0, =level_address_message
    bl uart_puts
    mov x0, x23
    bl  uart_put_hex

    tbz x23, #0, .Linvalid
    
    cmp x21, #12
    b.eq .Lfound

    and x19, x23, #DESCR_ADDR_MASK
    sub x21, x21, #9
    add x22, x22, #1
    b .Ltranslate_loop

.Lfound:
    and x0, x23, #DESCR_ADDR_MASK
    and x1, x20, #(PAGE_SIZE - 1)
    orr x0, x0, x1
    b   .Ldone

.Linvalid:
    mov x0, #0

.Ldone:
    ldp x23, x30, [sp], #16
    ldp x21, x22, [sp], #16
    ldp x19, x20, [sp], #16
    ret
```

- The loop covers the four levels, it stops when `shift` is 12 (`cmp x21, #12`), after reading the level 3 entry.
- The entry is kept in `x23`, because the UART calls overwrite `x0`-`x3`. The level is printed as an ASCII digit (`level + 48`).
- `tbz x23, #0, .Linvalid` stops the walk on an invalid descriptor. The test comes before the level 3 test, so an invalid level 3 entry returns 0.
- The result is the page address (`descriptor & DESCR_ADDR_MASK`) plus the offset inside the page (`va & 0xFFF`), so `translate(0x09000234)` returns `0x09000234` and not `0x09000000`.
- The two exits (found and invalid) share the same epilogue.

## Step 5: Enabling the MMU

Once the `M` bit of `SCTLR_EL1` is set, every fetch and every access goes through the tables of Step 4. Everything the kernel touches must therefore be mapped: code, stack, vector table, the whole heap, the UART and the GIC.

> See [Quick and Dirty AArch64 MMU setup](https://dannasman.github.io/aarch64-mmu.html) and the [`TCR_EL1`](https://developer.arm.com/documentation/ddi0601/2025-06/AArch64-Registers/TCR-EL1--Translation-Control-Register--EL1-) register page.

### `MAIR_EL1` and `TCR_EL1`

The `AttrIndx` field of a descriptor is only an index. `MAIR_EL1` gives each index a meaning:

| Index | Byte | Meaning |
| --- | --- | --- |
| 0 (`MT_DEVICE`) | `0x00` | Device-nGnRnE: no caching, no reordering (UART, GIC) |
| 1 (`MT_NORMAL`) | `0xFF` | Normal, write-back, read/write allocate (RAM) |

`TCR_EL1` describes how the tables are read. The choices that matter:

- `T0SZ = 16` and 4 KB granule: 48-bit addresses, which is what `map_page` assumes (indexes from bit 39).
- Table walks are write-back and inner shareable.
- `EPD1 = 1`: the high half of the address space (`TTBR1_EL1`) is disabled until Step 7, so a stray access faults cleanly.
- `IPS = 0`: 32-bit physical addresses, enough here and supported by every CPU.

```asm
.equ MAIR_VALUE,    ((MAIR_ATTR_DEVICE << (MT_DEVICE * 8)) | (MAIR_ATTR_NORMAL << (MT_NORMAL * 8)))
.equ TCR_VALUE,     (TCR_T0SZ | TCR_IRGN0 | TCR_ORGN0 | TCR_SH0 | TCR_TG0 | TCR_T1SZ | TCR_EPD1 | TCR_IRGN1 | TCR_ORGN1 | TCR_SH1 | TCR_TG1)
```

`MAIR_VALUE` is `0xFF00` and `TCR_VALUE` is `0xB5903510`, checked by assembling them in a throwaway file:

```bash
printf '.include "mm/mm.inc"\n.quad MAIR_VALUE\n.quad TCR_VALUE\n' > /tmp/t.s
aarch64-none-elf-gcc -Isrc -c /tmp/t.s -o /tmp/t.o
aarch64-none-elf-objdump -s -j .text /tmp/t.o
```

```text
 0000 00ff0000 00000000 103590b5 00000000
```

`mmu_config` writes them (`msr` writes a system register, `mrs` reads one). They have no effect while the MMU is off, so they are read back:

```asm
mmu_config:
    // Config MAIR_EL1
    ldr x0, =MAIR_VALUE
    msr mair_el1, x0

    // Config TCR_EL1
    ldr x0, =TCR_VALUE
    msr tcr_el1, x0

    isb
    ret
```

```text

TCR_EL1:  0x00000000B5903510
```

### `map_range`

Mapping the RAM takes 32768 pages, so `map_page` is wrapped in a loop. The first four arguments keep the order of `map_page`, `x4` is the size.

```asm
map_range:
    stp x19, x20, [sp, #-16]!
    stp x21, x22, [sp, #-16]!
    stp x23, x30, [sp, #-16]!

    mov x19, x0
    mov x20, x1
    mov x21, x2
    mov x22, x3
    add x23, x1, x4

.Lrange_loop:
    cmp x20, x23
    b.hs .Lrange_done

    mov x0, x19
    mov x1, x20 
    mov x2, x21 
    mov x3, x22 
    bl map_page

    add x20, x20, #PAGE_SIZE
    add x21, x21, #PAGE_SIZE
    b .Lrange_loop

.Lrange_done:
    ldp x23, x30, [sp], #16
    ldp x21, x22, [sp], #16
    ldp x19, x20, [sp], #16
    ret

```

### The identity map

With `va = pa`, the code keeps running at the same addresses once the translation starts.

| Region | Profile | Why |
| --- | --- | --- |
| RAM, `0x40000000` to `0x48000000` | `PAGE_RAM` | Code, stack, vectors, and the whole heap: `page_alloc` writes in the free pages |
| GIC, `0x08000000` (distributor and CPU interface, 2 x 64 KB) | `PAGE_DEVICE` | `gic_init`, IRQ handler |
| UART, `0x09000000` | `PAGE_DEVICE` | Every print |

`UART_BASE` moved to `src/uart/uart.inc`, like the GIC constants, so that `uart.s` and `mmu.s` share it.

```asm
mmu_map_identity:
    stp x19, x30, [sp, #-16]!

    mov x19, x0

    // Map RAM
    mov x0, x19
    ldr x1, =RAM_BASE
    ldr x2, =RAM_BASE
    ldr x3, =PAGE_RAM
    ldr x4, =RAM_SIZE
    bl map_range

    // Map GIC (distributor and CPU interface, contiguous)
    mov x0, x19
    ldr x1, =GICD_BASE
    ldr x2, =GICD_BASE
    ldr x3, =PAGE_DEVICE
    ldr x4, =GIC_SIZE
    bl map_range

    // Map UART
    mov x0, x19
    ldr x1, =UART_BASE
    ldr x2, =UART_BASE
    ldr x3, =PAGE_DEVICE
    ldr x4, =PAGE_SIZE
    bl map_range

    ldp x19, x30, [sp], #16
    ret
```

Pages used: 
- 1 level 1 table, 
- 2 level 2 tables (RAM, peripherals) 
- and 66 level 3 tables (64 for the RAM at 2 MB each, one for the GIC, one for the UART), so 69 pages. 

Checked with `translate`:


### Enabling the MMU

```asm
mmu_enable:
    dsb ish

    msr ttbr0_el1, x0

    tlbi vmalle1
    dsb ish
    isb

    mrs x1, sctlr_el1
    orr x1, x1, #SCTLR_M
    msr sctlr_el1, x1

    isb
    ret
```

- `dsb ish` waits until the descriptors are really in memory before the hardware walks them.
- `tlbi vmalle1` drops the cached translations, whose content is unknown at reset.
- `isb` flushes the pipeline so that the following instructions use the new state.
- `SCTLR_EL1` is read, modified, written back: it holds other bits, some reserved to 1.
- After the `msr sctlr_el1`, the address of the next instruction is translated. The identity map gives the same address, so execution simply continues.

### Caches

```asm
mmu_enable_caches:
    ic iallu
    dsb nsh
    isb

    mrs x0, sctlr_el1
    orr x0, x0, #SCTLR_C
    orr x0, x0, #SCTLR_I
    msr sctlr_el1, x0
    isb
    ret
```

`ic iallu` invalidates the instruction cache before it is enabled. `C` and `I` need two `orr`.

### Boot sequence and run

```asm
    // Initialize the physical memory manager
    bl pmm_init

    // Configure MAIR_EL1 and TCR_EL1 (the MMU is still off)
    bl mmu_config

    // Root translation table, filled with the identity map
    bl page_alloc
    mov x19, x0
    bl mmu_map_identity

    // Enable the MMU
    mov x0, x19
    bl mmu_enable

...

    // Enable the caches
    bl mmu_enable_caches
```

All of it runs before IRQs are unmasked.

### Limitations

- The data cache is not invalidated before being enabled: not needed on QEMU, done by the firmware on real hardware.
- The whole RAM is `PAGE_RAM`: writable and executable in EL1. Step 6 restricts individual pages.
- `TTBR1_EL1` is unused (`EPD1 = 1`) until Step 7.

## Step 6: Mappings beyond `va = pa`

Four experiments show that the hardware applies the descriptors:
- an alias,
- a read-only page, 
- an unmapped address 
- and a non-executable page.

### Profiles and kernel root

```asm
.equ PAGE_RAM_RO,        (PAGE_RAM | DESCR_AP_RO)       // read-only
.equ PAGE_RAM_NX,        (PAGE_RAM | DESCR_PXN)         // not executable in EL1
```

`mmu_enable` stores the root table in `kernel_root` (`.bss`), `_start` only keeps it in `x19`, which the exception handler overwrites.

`map_page` now ends with `dsb ishst` and `isb` beacause until now the tables were built before the MMU was on, they are now modified while the hardware walks them.

### The handler

An `eret` after a data abort would run the faulting instruction again, forever (for an abort, `ELR_EL1` points at the faulting instruction). `el_synchronous` now dispatches on the exception class:

| EC | Cause | Action |
| --- | --- | --- |
| `0x15` | `svc` | Return, as before |
| `0x25` | Data abort | Count it, skip the faulting instruction, return |
| other | Instruction abort, unexpected exception | Print and halt |

```asm
    lsr x1, x21, #26
    and x1, x1, #0x3F

    cmp x1, #0x15
    b.eq .Lsync_return

    cmp x1, #0x25
    b.ne .Lsync_halt

    ldr x0, =fault_count
    ldr x2, [x0]
    add x2, x2, #1
    str x2, [x0]

    add x19, x19, #4
    msr elr_el1, x19

.Lsync_return:
    ldp x29, x30, [sp], #16
    eret

.Lsync_halt:
    ldr x0, =message_unhandled_exception
    bl uart_puts
    b .
```

An AArch64 instruction is always 4 bytes, so `ELR_EL1 + 4` is the next one. `x19` holds `ELR_EL1` since `CALL_HANDLER`.

The handler overwrites `x0`-`x3`, `x19`-`x22` and `x30`, so the test keeps its values in `x25`-`x28`.

### Read the abort dump

| Line | Meaning |
| --- | --- |
| `EC` | Class of the exception: `0x25` = a load or store failed (data abort), `0x21` = an instruction fetch failed (instruction abort) |
| `FAR_EL1` | The virtual address that was accessed |
| Last byte of `ESR_EL1` | The cause. Bits [5:0] are the fault status code, bit 6 is set when the access was a **write** |

Two causes appear in the tests:

- **Translation fault** (`0x04` to `0x07`, the last digit is the level): the MMU walked the tables and found **no valid descriptor**, so nothing maps this address. The level is where the walk stopped.
- **Permission fault** (`0x0C` to `0x0F`): the MMU found the page descriptor, but its attributes **forbid this kind of access** (here read-only or non-executable).

### What the output shows

| Step | What the code does | What the output shows | What it proves |
| --- | --- | --- | --- |
| Alias | Writes `0xAAAA5555` at the page's own address, reads it at `0x10000000` | `Alias read: 0xAAAA5555` | Both addresses reach the same physical page: the translation really happens |
| Write to the read-only alias | Writes `0xBBBB6666` at `0x10000000` | `ESR_EL1` ends with `4F`: bit 6 set (a write) and status `0x0F` (permission fault, level 3). `FAR_EL1 = 0x10000000` | The walk reached the page descriptor (level 3), and its read-only bit refused the write |
| Reading the page afterwards | Reads the page through its own address | `After RO write: 0xAAAA5555` | The value did not change: the write was really blocked, not just reported |
| Unmapped address | Reads `0x20000000` | `ESR_EL1` ends with `06`: translation fault, level 2. `FAR_EL1 = 0x20000000` | Levels 0 and 1 are valid but the level 2 entry is empty: the walk stopped there, no descriptor to check |
| Counter and continuation | | `Faults: 0x2`, and the following lines still print | The handler skipped each faulting instruction instead of looping |

`FAR_EL1` is the **virtual** address of the access: `0x10000000` for the alias, not the physical address of the page.

### Not executable

The same page is mapped a third time at `0x10001000` with `PAGE_RAM_NX`, then the test jumps into it:

```asm

    mov x0, x25
    ldr x1, =0x10001000 
    mov x2, x26
    ldr x3, =PAGE_RAM_NX

```

```text
Jumping into the non-executable page
Synchronous exception caught!
ELR_EL1:  0x0000000010001000
ESR_EL1:  0x000000008600000F
EC:       0x0000000000000021
FAR_EL1:  0x0000000010001000

```

This test is different because the handler cannot continue. For a data abort it skips the failed `str` or `ldr` and resumes at the next instruction. Here the processor never fetched the instruction at `0x10001000`: there is no instruction to skip and no meaningful place to resume, so `el_synchronous` halts for every class other than `svc` and data abort.

What the output shows:

| Line | Meaning |
| --- | --- |
| `EC = 0x21` | An instruction **fetch** failed (a data abort would be `0x25`) |
| `ELR_EL1 = FAR_EL1 = 0x10001000` | The instruction the CPU tried to fetch is the jump target, which is also the faulting address |
| `ESR_EL1` ends with `0F` | Permission fault, level 3: the page descriptor was found, but `PXN` forbids executing from it |

The permission check comes before the fetch. If `PXN` had not been applied, the CPU would have started executing the content of the page (a data value followed by zeros, which decode as an undefined instruction, class `0x00`). Seeing `0x21` therefore proves the page was refused before anything was read from it.

This test stops the kernel, so it is not part of the normal boot.

## Step 7: Higher-half kernel

The kernel now runs at virtual addresses `0xFFFF000040000000` and above, translated by `TTBR1_EL1`. Later, user programs will own the low half (`TTBR0_EL1`) and the kernel stays visible in the high half whatever program runs.

### Position-independent code

`ldr x0, =symbol` loads an absolute address fixed by the linker. `adr x0, symbol` computes `PC + distance`, so it follows where the code actually runs: physical before the jump, virtual after.

| What is loaded | Instruction |
| --- | --- |
| Address of a label (message, variable, `_stack_top`...) | `adr` |
| A number (`UART_BASE`, `RAM_END`, `PAGE_RAM`...) | `ldr =` |
| `_heap_start` | `ldr =`: it is a physical number, see the linker |

This was done first, with the linker unchanged: the output of the kernel did not change.

### The linker

```text
KERNEL_PHYS      = 0x40000000;
KERNEL_VA_OFFSET = 0xFFFF000000000000;

ENTRY(_start_phys)

SECTIONS
{
    . = KERNEL_PHYS + KERNEL_VA_OFFSET;
    ...
    .text : AT(ADDR(.text) - KERNEL_VA_OFFSET) { *(.text*) }
    // ... (same for .rodata, .data, .bss, .stack)

    . = ALIGN(4096);
    _heap_start = ABSOLUTE(. - KERNEL_VA_OFFSET);

    _start_phys = _start - KERNEL_VA_OFFSET;
}
```

- The virtual address of each section is high, its load address (`AT`) is physical.
- The entry point must be physical. QEMU jumps to it with the MMU off, hence `_start_phys`.
- `_heap_start` is `ABSOLUTE`. The allocator manages physical memory, so the bound must stay a physical number whatever the code runs at.

A first version kept `. = 0x40000000;` as the start address: the load address `0x40000000 - 0xFFFF000000000000` wrapped around to `0x0001000040000000`, which `readelf` showed as the segment's `PhysAddr` and as a wrong `Entry`. Checks:

```bash
aarch64-none-elf-readelf -lW build/kernel.elf              # VirtAddr 0xffff000040000000, PhysAddr 0x40000000
aarch64-none-elf-readelf -h build/kernel.elf | grep Entry  # Entry point 0x40000000
```

With the image linked high but still running at its physical addresses, the output did not change and the `ELR_EL1` of the exceptions stayed `0x4000....`, which is the real PC.

### The high map (`TTBR1_EL1`)

A **direct map** of the whole RAM at `PA + KERNEL_VA_OFFSET`, in its own root table. The kernel image (linked in that range), the stack and the heap are all covered.

```asm
mmu_map_high:
    stp x19, x30, [sp, #-16]!

    mov x19, x0

    ldr x3, =RAM_BASE
    ldr x2, =KERNEL_VA_OFFSET
    add x1, x3, x2

    mov x2, x3
    ldr x3, =PAGE_RAM
    ldr x4, =RAM_SIZE

    mov x0, x19
    bl map_range

    ldp x19, x30, [sp], #16
    ret
```

`map_page` needs no change, it only looks at the bits [47:12] of the virtual address, and the top 16 bits (all ones) only make the hardware pick `TTBR1_EL1`.

`mmu_enable` takes the two roots (`x0` for `TTBR0_EL1`, `x1` for `TTBR1_EL1`) and writes both before setting the `M` bit; its scratch register moved to `x2`. `EPD1` is removed from `TCR_VALUE` (`TCR_EL1 = 0xB5103510`) because the walks in `TTBR1_EL1` are now allowed.

First check, with the kernel still running at its physical address, a page written through the identity map is read back through its high address.

```text
High alias read: 0x00000000AAAA5555
```

The address `0xFFFF0000....` exists only in the `TTBR1_EL1` table, so the hardware translated it.

### The jump from low to high

```asm
    // Transition to the high-half kernel
    ldr x0, =high_half_entry
    br  x0

high_half_entry:
    // Switch to the high virtual stack
    adr x0, _stack_top
    mov sp, x0

    // Switch exception vectors to their high virtual address
    adr x0, _exception_vector_table
    msr vbar_el1, x0
    isb
```

This is the one deliberate `ldr =symbol`. The address computed by the linker (high) is exactly what is wanted while the PC is still physical. After the `br`, the PC is high, so every `adr` returns a high address, therefore the stack and the vectors are re-pointed there.

If the jump failed, `VBAR_EL1` would still point at the physical vector table, reachable through the identity map, in that case the handler would print an instruction abort and halt.

## Step 8: Tests

The steps 0 to 7 work but were checked by reading values by hand. The goal of this step is to create automated checks. The file `src/tests/tests.s` will compare values instead of printing them for a human to read. The script `scripts/test.sh` runs the kernel under QEMU and decides pass or fail, according to th output. A CI workflow will run it on every push.

### `check`: the comparison primitive

Every test compare a value read to a value expected, print `PASS` or `FAIL`, and count both.

```asm
check:
    stp x19, x20, [sp, #-16]!
    stp x21, x30, [sp, #-16]!

    mov x19, x0          // test name
    mov x20, x1          // value read
    mov x21, x2          // value awaited

    // test_count += 1
    adr x3, test_count
    ldr x4, [x3]
    add x4, x4, #1
    str x4, [x3]

    cmp x20, x21
    b.ne .Lcheck_fail

    // Success message
    adr x0, message_pass
    bl uart_puts
    mov x0, x19
    bl uart_puts

    b .Lcheck_done

    // Fail message
.Lcheck_fail:
    adr x0, message_fail
    bl uart_puts
    mov x0, x19
    bl uart_puts
    adr x0, message_got
    bl uart_puts
    mov x0, x20
    bl uart_put_hex
    adr x0, message_expected
    bl uart_puts
    mov x0, x21
    bl uart_put_hex
    adr x0, message_close_parenthesis
    bl uart_puts

    // test_failures += 1
    adr x3, test_failures
    ldr x4, [x3]
    add x4, x4, #1
    str x4, [x3]

.Lcheck_done:
    ldp x21, x30, [sp], #16
    ldp x19, x20, [sp], #16
    ret
```

`tests_run` calls every test suite, then prints :
- `ALL TESTS PASSED` 
- or `TESTS FAILED: 0x<count>` 

depending on `test_failures`.

### Hardware translation: `hw_translate`

`hw_translate` asks the MMU itself, using `AT S1E1R` (Address Translate, stage 1, EL1, read) and `PAR_EL1` (Physical Address Register) for the result:

```asm
hw_translate:
    mov x1, x0
    at s1e1r, x1
    isb
    mrs x2, par_el1
    tbnz x2, #0, .Lhw_fail

    and x0, x2, #DESCR_ADDR_MASK
    and x1, x1, #(PAGE_SIZE - 1)
    orr x0, x0, x1
    ret

.Lhw_fail:
    mov x0, #0
    ret
```

Bit 0 of `PAR_EL1` (`F`) is set when the translation fails. A `check_at name, va, expected` macro wraps `hw_translate` and `check` for the repetitive cases.

### The test suites

There is six groups in `tests_run`, each prefixed so failures are easy to locate:

| Prefix | Test | What it checks |
| --- | --- | --- |
| `REGS:` | `test_mmu_registers` | `MAIR_EL1`, `TCR_EL1`, and the `M`/`C`/`I` bits of `SCTLR_EL1` |
| `PMM:` | `test_pmm` | two distinct 4 KB-aligned zeroed pages; `free_count` drops by 2; the last freed page is reused; the count is restored after freeing both |
| `AT:` | `test_translation` | hardware translation of the identity-mapped RAM, UART and GIC; the RAM's high alias; an unmapped address and the address right after the RAM (both refused); the kernel's own code address |
| `LOC:` | `test_kernel_location` | the PC, the stack pointer and `VBAR_EL1` are all in the high half (`0xFFFF...`) |
| `ALIAS:` | `test_high_alias` | a page written through the identity map reads back through its high alias, and the reverse |
| `PERM:` | `test_permissions` | a read-only alias reads the page; a write to it is blocked (the page keeps its value) and counted in `fault_count`; reading an unmapped address is also blocked and counted |

### `scripts/test.sh` and `make test`

The kernel never terminates on its own (it ends in `b .`), so the script runs QEMU in the background, polls the log, and kills QEMU as soon as `ALL TESTS PASSED` and a `Tick:` line both appear, or as soon as a `FAIL:` line appears.

```bash
qemu-system-aarch64 -M virt -cpu cortex-a57 -m 128M -nographic \
    -kernel "$KERNEL" > "$LOG" 2>&1 &
pid=$!
...
while [ "$SECONDS" -lt "$deadline" ]; do
    ...
    if grep -q '^FAIL:' "$LOG"; then break; fi
    if grep -q 'ALL TESTS PASSED' "$LOG" && grep -q 'Tick: ' "$LOG"; then break; fi
    if ! kill -0 "$pid" 2>/dev/null; then break; fi
    sleep 0.1
done
kill "$pid" 2>/dev/null
```

`make test` builds and then runs the script:

```makefile
test: $(OUTPUT)
	@chmod +x scripts/test.sh
	@./scripts/test.sh
```
