# v0.2 - Exceptions and Interrupts

---

## Step 0: AArch64 Exception Model

For this part, I used the official [Learn the architecture - AArch64 Exception Model](https://support.arm.com/documentation/102412/0103?lang=en) documentation.

### Exception levels

| Level | Typical use | Privilege |
| --- | --- | --- |
| `EL0` | Application code | Lowest |
| `EL1` | OS kernel | High |
| `EL2` | Hypervisor | Higher |
| `EL3` | Firmware/Security monitor | Highest |

Taking an exception can only raise or keep the same EL. Only an exception *return* can lower it. Exceptions are never taken to EL0.

### Key system registers

| Register | Description |
| --- | --- |
| `ELR_ELx` | Return address after the exception |
| `ESR_ELx` | Cause of the exception (synchronous/SError only) |
| `SPSR_ELx` | Saved `PSTATE` at the time of the exception |
| `VBAR_ELx` | Base address of the exception vector table |

### Synchronous vs asynchronous

- **Synchronous**: caused directly by the current instruction (`svc`, invalid instruction, MMU fault). Return address has an architecturally-defined relationship with the faulting instruction. Cannot be masked.
- **Asynchronous** (= interrupts: IRQ/FIQ/SError): external events (timers, peripherals). Can be masked via `PSTATE.DAIF`. Handled through the ARM **GIC**, see Step 8.

### The vector table

Each EL has its own table at `VBAR_ELx`, 16 entries of 128 bytes (32 instructions) each, 2 KB aligned:

| Offset | Type | Source |
| --- | --- | --- |
| `+0x000` | Synchronous | current EL, SP_EL0 |
| `+0x080` | IRQ | current EL, SP_EL0 |
| `+0x180` | SError | current EL, SP_EL0 |
| `+0x200` | **Synchronous** | **current EL, SP_ELx** |
| `+0x280` | **IRQ** | **current EL, SP_ELx** |
| `+0x380` | SError | current EL, SP_ELx |
| `+0x400`-`+0x780` | (lower EL, AArch64/AArch32) | not used, no EL0 yet |

This kernel only runs at EL1 with no EL0, so only the two bolded entries (`+0x200`, `+0x280`) matter; the other 14 are stubs.

### Returning from an exception

`ERET` atomically restores `PSTATE` from `SPSR_ELx` and branches to `ELR_ELx`. For `SVC`, `ELR_EL1` holds the address of the instruction *after* the `svc`.

## Step 1: The Exception Vector Table

`src/exceptions/vectors.s`:

```asm
.section .text.vectors

.global _exception_vector_table

.macro CALL_HANDLER handler
vector_\handler:
    mrs x19,  ELR_EL1
    mrs x20,  SPSR_EL1
    mrs x21,  ESR_EL1

    mov x0, sp

    bl \handler
.endm

.macro UNUSED_VECTOR
1:
    wfe
    b   1b
.endm

.align 11

_exception_vector_table:
.org 0x000
    UNUSED_VECTOR
.org 0x080
    UNUSED_VECTOR
.org 0x100
    UNUSED_VECTOR
.org 0x180
    UNUSED_VECTOR

.org 0x200
    CALL_HANDLER el_synchronous
.org 0x280
    UNUSED_VECTOR
.org 0x300
    UNUSED_VECTOR
.org 0x380
    UNUSED_VECTOR

.org 0x400
    UNUSED_VECTOR
.org 0x480
    UNUSED_VECTOR
.org 0x500
    UNUSED_VECTOR
.org 0x580
    UNUSED_VECTOR

.org 0x600
    UNUSED_VECTOR
.org 0x680
    UNUSED_VECTOR
.org 0x700
    UNUSED_VECTOR
.org 0x780
    UNUSED_VECTOR
.org 0x800
```

- `.align 11` = 2^11 = 2048 bytes, the alignment `VBAR_EL1` requires.
- `.org 0xNNN` forces each entry to its exact offset; if a macro expands to more than 128 bytes, assembly fails instead of silently overlapping the next entry.
- `UNUSED_VECTOR` uses a numeric local label (`1:`/`b 1b`) so it can be expanded multiple times in the same file without duplicate-symbol errors.
- `CALL_HANDLER` saves `ELR_EL1`/`SPSR_EL1`/`ESR_EL1` into callee-saved registers (`x19`-`x21`, safe across the calls made inside the handler), then jumps to the real handler with the stacked context pointer in `x0`.

> I took inspiration from the file [src/_arch/aarch64/exception.s](https://github.com/rust-embedded/rust-raspberrypi-OS-tutorials/blob/master/11_exceptions_part1_groundwork/src/_arch/aarch64/exception.s) from the project [rust-raspberrypi-OS-tutorials
](https://github.com/rust-embedded/rust-raspberrypi-OS-tutorials).

## Step 2: Configuring VBAR_EL1

In `src/boot/boot.s`, right after the stack is set up:

```asm
    ldr x0, =_exception_vector_table
    msr vbar_el1, x0
```

`VBAR_EL1` is undefined after reset, so this must run before any code that could trigger an exception.

## Step 3: `uart_put_hex`

Added to `src/uart/uart.s`, to print a 64-bit register value in hexadecimal (needed since `uart_puts` only handles ASCII strings):

```asm
uart_put_hex:
    stp x19, x20, [sp, #-32]!
    stp x30, xzr, [sp, #16]

    mov x19, x0
    mov x20, #16

hex_loop:
    lsr x3, x19, #60
    and x3, x3, #0xF

    ldr x2, =hex_chars
    ldrb w0, [x2, x3]
    bl uart_putc

    lsl x19, x19, #4

    subs x20, x20, #1
    b.ne hex_loop

    ldp x30, xzr, [sp, #16]
    ldp x19, x20, [sp], #32
    ret

.section .rodata.uart

hex_chars:
    .asciz "0123456789ABCDEF"
```

- Extracts one nibble at a time from the top of `x19` (`lsr #60`/`and #0xF`), looks it up in `hex_chars`, prints it, then shifts `x19` left by 4 so the next nibble rises to the top (16 iterations for 64 bits).
- `x2` (the table address) is reloaded every iteration since `uart_putc` clobbers it via `w2`.
- Frame is 32 bytes (`x19`, `x20`, `x30`, padding via `xzr`) to keep `sp` 16-byte aligned in one single reservation.

## Step 4: The Synchronous Handler

`src/exceptions/handlers.s`:

```asm
.section .text.handlers

.global el_synchronous
.extern uart_puts
.extern uart_put_hex

el_synchronous:
    stp x29, x30, [sp, #-16]!

    ldr x0, =message_synchronous
    bl uart_puts

    ldr x0, =message_prefix_elr_el1
    bl uart_puts
    mov x0, x19
    bl uart_put_hex

    ldr x0, =message_prefix_spsr_el1
    bl uart_puts
    mov x0, x20
    bl uart_put_hex

    ldr x0, =message_prefix_esr_el1
    bl uart_puts
    mov x0, x21
    bl uart_put_hex

    b .

.section .rodata.handlers

message_synchronous:
    .asciz "Synchronous exception caught!\n"

message_prefix_esr_el1:
    .asciz "ESR_EL1: 0x"

message_prefix_elr_el1:
    .asciz "\nELR_EL1: 0x"

message_prefix_spsr_el1:
    .asciz "\nSPSR_EL1: 0x"
```

`x19`/`x20`/`x21` (set by `CALL_HANDLER`) survive the `uart_puts`/`uart_put_hex` calls since those respect the callee-saved convention. No `eret`: the handler halts after printing, so `x29`/`x30` are saved defensively but never actually restored.

## Step 5: Triggering the Exception

`src/boot/boot.s`, complete:

```asm
.section .text.boot

.global _start
.extern _exception_vector_table
.extern uart_puts

_start:
    ldr x0, =_stack_top
    mov sp, x0

    ldr x0, =_exception_vector_table
    msr vbar_el1, x0

    ldr x0, =message
    bl uart_puts

    svc #0

    b .

.section .rodata.boot

message:
    .asciz "Hello, AArch64!"
```

Execution flow:
```text
    _start
        |
        +-- setup stack
        |
        +-- configure VBAR_EL1
        |
        +-- print "Hello, AArch64!"
        |
        +-- svc #0 -----------------------+
                                           |
                              vector_el_synchronous (+0x200)
                                           |
                              save ELR_EL1/SPSR_EL1/ESR_EL1
                                           |
                                    el_synchronous
                                           |
                          print exception message + 3 register dumps
                                           |
                                  infinite loop (`b .`)
```

`b .` after `svc #0` is dead code today (the handler never returns), kept as a guard in case `el_synchronous` is later changed to `eret`.

## Step 9: The GIC

For this part, I used the official [ARM Generic Interrupt Controller Architecture Specification (GICv2)](https://developer.arm.com/documentation/ihi0048/latest/). QEMU `virt` with `cortex-a57` implements a **GICv2**.

### What is the GIC?

Without a GIC, each processor would need dedicated wiring for every interrupt source. The **Generic Interrupt Controller (GIC)** is Arm's standard interrupt controller, it is a centralized hardware resource between all interrupt sources (peripherals, timers, other processors) and the CPU, exposed through memory-mapped registers (`GICD_*`, `GICC_*`).

> Like the UART registers, see [v01.md](v01.md).

### Partitioning

| Block | Role | Prefix |
| --- | --- | --- |
| **Distributor** | Centralizes sources, prioritizes, decides target CPU interface(s) | `GICD_*` |
| **CPU interface** | Per-processor: priority masking, delivers the signal | `GICC_*` |

### Interrupt lifecycle

1. **Acknowledge**: read `GICC_IAR`, returns the pending ID, moves it to active.
2. **Handle**: the handler runs.
3. **Complete**: write the same value back to `GICC_EOIR`.

### Interrupt ID ranges

| Range | Type |
| --- | --- |
| 0-15 | SGI (Software-Generated Interrupt), it is triggered by writing `GICD_SGIR`, used for this step's test |
| 16-31 | PPI |
| 32-1019 | SPI |

### GICD_BASE / GICC_BASE on QEMU `virt`

```bash
qemu-system-aarch64 -M virt -cpu cortex-a57 -machine dumpdtb=virt.dtb -nographic
dtc -I dtb -O dts virt.dtb | grep -A 5 intc

reg = <0x00 0x8000000 0x00 0x10000 0x00 0x8010000 0x00 0x10000>;
```

Per the standard `arm,gic` device tree binding, Distributor is listed first:

| Register | Address |
| --- | --- |
| `GICD_BASE` | `0x08000000` |
| `GICC_BASE` | `0x08010000` |

## Step 10: GIC Driver


`src/gic/gic.inc` contains offsets shared across files (included):

```asm
.equ GICD_BASE,       0x08000000
.equ GICC_BASE,       0x08010000

.equ GICD_CTLR,       0x000
.equ GICD_ISENABLER0, 0x100
.equ GICD_SGIR,       0xF00

.equ GICC_CTLR,       0x000
.equ GICC_PMR,        0x004
.equ GICC_IAR,        0x00C
.equ GICC_EOIR,       0x010
```

`src/gic/gic.s`:

```asm
.section .text.gic

.global gic_init

.include "gic/gic.inc"

gic_init:
    // Distributor: enable Group 0 forwarding
    ldr x0, =GICD_BASE
    mov w1, #0x1
    str w1, [x0, #GICD_CTLR]

    // Distributor: enable SGI 0
    ldr x0, =GICD_BASE
    mov w2, #0x1
    str w2, [x0, #GICD_ISENABLER0]

    // CPU interface: let all priorities through
    ldr x0, =GICC_BASE
    mov w3, #0xFF
    str w3, [x0, #GICC_PMR]

    // CPU interface: enable Group 0 signaling
    ldr x0, =GICC_BASE
    mov w4, #0x1
    str w4, [x0, #GICC_CTLR]

    ret
```

> `.include` pastes the file's content locally into each `.s` that includes it. It is necessary because an offset used as an immediate (`[x0, #GICD_SGIR]`) must be known to the assembler at assemble time. The Makefile passes `-Isrc` so `.include "gic/gic.inc"` resolves relative to `src/`.

## Step 11: Wiring the IRQ Vector and Handler

`src/exceptions/vectors.s`, `+0x280` entry now routes to a real handler instead of a stub:

```asm
.org 0x280
    CALL_HANDLER el_irq
```

`src/exceptions/handlers.s`:

```asm
el_irq:
    stp x22, x30, [sp, #-16]!

    // moves the interrupt to active
    ldr x0, =GICC_BASE
    ldr w22, [x0, #GICC_IAR]

    ldr x0, =message_irq
    bl uart_puts

    ldr x0, =message_prefix_iar
    bl uart_puts
    mov x0, x22
    bl uart_put_hex

    ldr x0, =message_newline
    bl uart_puts

    // write back the exact raw value read from GICC_IAR
    ldr x0, =GICC_BASE
    str w22, [x0, #GICC_EOIR]

    ldp x22, x30, [sp], #16
    eret
```

## Step 12: Triggering the SGI, and Returning Properly

Both `el_synchronous` and `el_irq` initially just looped forever (`b .`) after printing. Added a symmetric `ldp` + `eret` to both handlers (shown above and in Step 4) so control returns to `_start` right after the triggering instruction.


`src/boot/boot.s`, final:

```asm
.section .text.boot

.global _start
.extern _exception_vector_table
.extern gic_init
.extern uart_puts

.include "gic/gic.inc"

_start:
    ldr x0, =_stack_top
    mov sp, x0

    ldr x0, =message
    bl uart_puts

    // VBAR_EL1 must be set before any exception can occur
    ldr x0, =_exception_vector_table
    msr vbar_el1, x0

    // Must run after VBAR_EL1 and before IRQ unmask
    bl gic_init

    msr daifclr, #2

    // Provoke Synchronous exception
    svc #0

    // Provoke IRQ exception
    ldr x0, =GICD_BASE
    mov w1, #0x2000000
    str w1, [x0, #GICD_SGIR]

    b .

.section .rodata.boot

message:
    .asciz "Hello, AArch64!\n"
```

`0x2000000` = `GICD_SGIR` value: `TargetListFilter = 0b10` (bits 25:24, target self only) `| SGI ID 0` (bits 3:0).
